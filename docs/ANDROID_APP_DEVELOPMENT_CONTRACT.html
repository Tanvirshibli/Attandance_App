2. Project Overview

The Developers shall develop a native-packaged Android application that enables Client employees to manage attendance with face verification and GPS, and enables the Client to monitor sales and field personnel through periodic location tracking.

The Application shall integrate with the Client’s existing backend systems:

  • HRM backend — employee authentication (JWT), profile, face registration storage, leave, holidays, and payroll-related views.
  • ZKTeco / attendance backend — attendance punches, device identity, geo-location uploads, mobile API configuration, and attendance history.
Purpose. A single employee-facing Android app combining face-verified check-in/check-out, attendance reporting, leave self-service, field geo tracking with live map, and role-gated sales information — configured dynamically from the Client’s attendance administration dashboard.

4. Platform & Delivery Format

  • Target platform: Android only (iOS is out of scope).
  • Minimum supported OS: Android 8.0 (API 26).
  • Required permissions: camera; fine/coarse and background location; internet; foreground service (location); notifications; boot completed / wake lock as needed for geo tracking.
  • Handoff: signed or unsigned release APK (or App Bundle if requested), source project access as agreed, and brief operator documentation.
  • Offline behaviour: partial — geo pings may queue locally when upload fails; login and core attendance require network connectivity.

5. Modules & Deliverables

The Developers shall deliver the following functional modules as part of the Application. Feature availability for Sales and Payments may be controlled by remote feature flags configured from the Client’s attendance administration dashboard.

5.1 Authentication & Session Core

Email/password login against the HRM API with JWT session management, profile hydration, secure logout, token refresh with retry on unauthorized responses, and persistent session across app restarts.

5.2 Server Bootstrap & Dynamic API Configuration Core

First-launch server bootstrap to capture the attendance (ZKTeco) base URL; fetch and cache mobile app configuration (base URLs, endpoint paths, feature flags, geo interval); refresh configuration after login and on app resume. Administrators map API paths from the ZKTeco web dashboard without requiring an app store update for URL changes.

5.3 Face Registration Attendance

Multi-angle live face enrollment (straight, left, right, up, down) with placement and quality gates, same-person validation across captures, on-device embedding generation, and sync of face templates to the HRM backend for the enrolled employee.

5.4 Face-Verified Attendance (Check-In / Check-Out) Attendance

Separate check-in and check-out flows with randomized liveness challenges (look straight, smile, blink, turn left/right), on-device identity matching against enrolled templates, GPS capture with reverse geocoding on successful punch, submission to the attendance API with employee and device identifiers, and alignment with the Client’s device registry.

5.5 Home Dashboard Attendance

Employee greeting and identity, today’s clock status and hours, monthly KPI summary (Present / Absent / Holiday / Leave), weekly hours chart, and recent attendance list merged from attendance and HRM data sources as applicable.

5.6 Attendance History & Report Attendance

Filterable attendance history with monthly summary; full attendance report including punch timeline, face-verified indicator, GPS address where available, and summary cards.

5.7 Leave Management HR

Leave hub with balance snapshot and upcoming holidays; leave balance detail; leave history; and leave application (leave types and submission) via HRM APIs.

5.8 Geo Tracking (Field / Sales Person Tracking) Tracking

Toggleable location tracking with configurable interval (default five minutes); live map with GPS marker, accuracy circle, history pins, and recenter; manual capture; foreground timer and background WorkManager capture; ongoing notification while tracking; local offline queue when upload fails; upload and history via attendance geo-location APIs.

5.9 Sales Info Sales

Eligibility gate based on the Client’s sales-employee list; feature-flag control; sales information UI (target, orders, revenue, conversion metrics) prepared for connection to the Client’s sales product backend when available.

5.10 Payments Hub HR

Feature-flag-gated payment hub for post-loan payment, payment reports, and payroll slip views via HRM APIs, with a clear unavailable state when the flag is disabled.

5.11 Profile, Settings & Alerts Shell

Employee profile from HRM; settings entry points (including location services / geo tracking); services hub navigation to reports, leave, payments, sales, and geo; alerts tab UI; sign out.

5.12 Primary user journeys (acceptance reference)

  1. Bootstrap attendance server URL → download endpoint configuration → Login → Home.
  2. Register face (multi-angle) → sync templates to HRM.
  3. Check in / out → liveness → face match → GPS → punch API.
  4. Enable geo tracking → periodic/background pings → map and history.
  5. Apply leave / view payments / open Sales Info when flagged and eligible.
